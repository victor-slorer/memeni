### truefalse
In Python, `a < b < c` means `(a < b) < c`.
- answer: false
- explain: Python chains comparisons, so it means `a < b and b < c` (with `b` evaluated once); in C, `a < b < c` really is `(a < b) < c`, comparing 0 or 1 with c.

### truefalse
Adding an index speeds up both reads and writes on a table.
- answer: false
- explain: An index (usually a B-tree) speeds up lookups, joins and sorting on its columns, but every INSERT, UPDATE and DELETE must also update it, and it takes space.

### written
What is the lower bound on the number of comparisons for comparison-based sorting?
- answer: Ω(n log n) | O(n log n) | n log n | nlogn | omega(n log n)
- explain: There are n! possible orderings and each comparison has two outcomes, so you need at least log2(n!) ≈ n log n comparisons; counting and radix sort avoid the bound by not comparing.

### written

### written
What is the time complexity of the naive recursive Fibonacci, `fib(n) = fib(n-1) + fib(n-2)`?
- answer: O(2^n) | O(2ⁿ) | 2^n | exponential | O(φ^n)

- answer: double descent
- explain: Test error follows the classic U-curve, peaks around the point where the model can just interpolate the training data, then decreases again in the over-parameterised regime (Prince ch. 8).
